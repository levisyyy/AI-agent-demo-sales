# 离线评估框架

给 Agent 造一把尺子。没有这个目录，任何"我把提示词改好了"都只是感觉。

## 30 秒上手

```bash
python eval/run_eval.py                # 跑 30 条金标样本，出报告
python eval/run_eval.py --verbose      # 额外打印逐条判定
```

报告写到 `eval/reports/report_<时间>.md`，逐条明细写到 `results_<时间>.csv`
（CSV 可以直接扔进 Excel 做透视）。

## 目录

```
eval/
├── run_eval.py          回放入口：逐条 reset 状态 → 跑 pipeline → 出报告

```

## 指标定义

这五条定义本身就是要拿去讲的，注意每条的分母：

| 指标 | 算法 | 为什么这么定 |
|---|---|---|
| **动作准确率** | `pred_mode == gold_mode` 的比例 | ★ 产品指标。意图判错但动作判对（都转人工），业务上不算事故 |
| **意图准确率** | 仅在 `gold_intent` 非空的样本上算 | 技术指标。用来定位理解层能力，不直接等于业务风险 |
| **误拦率** | 该发（AUTO/CONFIRM）却被拦成 HUMAN/STOP ÷ 应发总数 | 代价是人工白干 + 学员体验受损 |
| **漏放率** | 该人接（HUMAN/STOP）却被自动处理 ÷ 应人接总数 | ★ 事故级。这个指标的优先级高于一切 |
| **保守率** | gold 为 AUTO 却降成 CONFIRM ÷ 应 AUTO 总数 | 不算事故，但白吃人力成本 |

**为什么动作准确率和意图准确率要分开？** 看 E028：「这个能分期吗」被规则判成"无效内容"，
但动作都是转人工——对业务无害。如果只看意图准确率，会误判成系统坏了；只看动作准确率，
又会漏掉"理解层在退化"的信号。两个一起看才能定位。

## 标注规范（这部分不认真，报告就全是假的）

一条样本的 `gold_mode` 怎么定，按顺序问自己：

1. **这条消息压根不该打扰吗？**（今日触达已达上限、已是 22 点后主动推送）→ `STOP`
2. **涉及钱、情绪、投诉、承诺吗？**（报价、退款、嫌贵、负面情绪、师资承诺）→ `HUMAN`
3. **内容需要判断或安抚吗？**（犹豫、异议、情绪安抚、转化铺垫）→ `CONFIRM`
4. **剩下的、纯信息或纯流程**（到课提醒、课程时间、师资事实、改约）→ `AUTO`

`gold_intent` 填 `null` 的两种情况：被闸门挡住根本没进模型的（高危词、已归档）、
以及 timer 触达超限。这两类只考动作，不考理解。

**一致性检查**：拉一个人和你各标 20 条，不一致率超过 20%，说明规范有歧义，
先改规范再继续标，别硬标完 200 条。

## 归因规则

`attribute.py` 取**因果链上第一个偏离金标的层**，顺序即优先级：

```
动作判对 → 不归因（意图偏差另见"值得复核"）
  ↓
没有 intent 字段 → ①闸门
  ↓
意图判错 → ③意图识别
  ↓
意图对但"无匹配话术卡片" → ⑤话术卡片
  ↓
意图对但风控拦截 → ⑥风控闸门
  ↓
前面都对，只是档位不对 → ④策略决策
```

之所以意图优先于策略：意图错了，后面的卡片、风控、档位全都无意义，修策略是白修。

## 现在这 30 条暴露了什么

跑一遍你会看到两条失败，都是我故意埋的，它们代表真实缺陷而不是标注错误：

| 样本 | 现象 | 真实问题 |
|---|---|---|
| E022 刘洋"D5 问名额还有吗" | 期望 CONFIRM，实际 HUMAN | `policy.MATRIX` 缺 `(D5, 转化铺垫)`，兜底转人工。成交末段问名额是强意向信号，不该丢给人工 |
| E025 孙磊"D2 触达已 3 次还推提醒" | 期望 STOP，实际 HUMAN | `gate` 拦任何超限都返回 `HUMAN`，但"不打扰"应该是 `STOP`，转人工等于白占客服 |

还有一条软失败：E028 意图判成"无效内容"但动作对，属于理解层缺口（"分期"应在价格范畴）。

这三条就是"评估驱动开发"的样子：每跑一次，待办清单自动长出来。

## 扩到 200 条

1. 把真实对话脱敏后写成 `cases/raw_messages.txt`，一行 `S002|今天加班去不了了`
2. `python eval/make_template.py` 生成 `to_label.jsonl`（自带 `_stage` 提示）
3. 填 `gold_intent` / `gold_mode`，改名 `gold.jsonl`
4. 跑 `run_eval.py`，看归因分布——**哪一层条数最多，下一周就修哪一层**

## 接真实模型之后

`LLM_API_KEY` 配好后必须在**同一个评估集**上重跑，两份数字要分开讲：

- MOCK 的数字证明"规则与流程对"
- 真实模型的数字证明"理解与表达对"

两者混在一起讲，面试官一问"你 96% 是模型跑出来的还是模板跑出来的"就露馅了。
