## 为 AI 督学 Agent 搭建离线评估框架（简历项目关键一环）

### 背景
用户以此项目为简历代表作，缺"度量"。目标：把"感觉好一点"变成可归因的数字。

### 交付物 `eval/`
- `run_eval.py` 回放入口：每条样本前 `store.reset()` 保证独立，时间固定 19:30 避开静默时段
- `dataset.py` 金标集加载 + 严格校验（缺字段 / mode 非法 / 意图名拼错 均直接报错，已实测）
- `metrics.py` 五类指标 + 混淆矩阵 + 纯标准库终端表格（中文按 2 格对齐）
- `attribute.py` 按「因果链上第一个偏离金标的层」归因
- `make_template.py` 从 `raw_messages.txt` 生成待标注骨架
- `cases/gold.jsonl` 30 条人工标注（覆盖 D1–D5、四档权限、gate 拦截、低置信度）
- `reports/` 输出 md 报告 + csv 明细；`TRACE_PATH` 环境变量隔离评估留痕（改 `agent/trace.py`）

### 指标口径（关键设计，勿改）
- **动作准确率**是产品指标；**意图准确率**是技术指标。二者必须分开：意图错但动作对（E028）业务无害。
- **漏放率**（该人接却被自动处理）优先级最高，是事故级。
- 误拦率 / 保守率 分开统计：前者白干人工，后者白吃人力。

### 归因规则（踩过的坑）
初版把闸门"正拦"（gold=HUMAN 且确实拦了）也算成失败，导致归因虚高 3 条。
修正：**动作判对即不归因**，只对 `pred_mode != gold_mode` 的样本定位。

### 故意埋的 3 条缺陷（已全部被正确抓到）
| 样本 | 现象 | 真实缺陷 |
|---|---|---|
| E022 D5"名额还有吗" | CONFIRM→HUMAN，归因④策略决策 | `MATRIX` 缺 `(D5, 转化铺垫)` |
| E025 D2 触达 3 次仍推提醒 | STOP→HUMAN，归因①闸门 | `gate` 一律返回 HUMAN，"不打扰"应是 STOP |
| E028"这个能分期吗" | 动作对、意图错 | 关键词规则识别不到"分期"，应属价格咨询 |

**MOCK 数字只能证明规则与流程，接真模型后必须同集重跑并分开报。**
