# 为什么不用 Dify / LangChain —— 对比分析

> 结论先行：**Dify 能拖出这个项目的六成，但拖出来的不是这个产品。**
> 差距的四成本质上不是"功能多少"，而是：这个项目的核心资产是**策略矩阵**和**评估闭环**，
> 而这两样在低代码平台里都是二等公民。

---

## 一、七层逐一映射到 Dify

| 本项目 | Dify 里的对应做法 | 体验 |
|---|---|---|
| ③意图识别 | LLM 节点 + 结构化输出 | ✅ 直接拖 |
| ⑤话术生成 | LLM 节点 + 知识库检索节点 | ✅ 直接拖 |
| ②上下文装配 | 变量拼接节点 | ✅ 能做 |
| ⑥风控闸门 | 代码节点写正则 | ⚠️ 能做，但它是普通节点，**后续节点可以绕过它** |
| ①闸门 | 条件分支 + 代码节点 | ⚠️ 能做，但"高危词表"散落在画布条件里 |
| ④策略矩阵 | 50 条 `(Stage, 意图)` 规则 | 🔴 灾难区：嵌套 IF/ELSE 拖 50 条没法维护；全塞代码节点等于把 Python 藏进画布 |
| ⑦状态回写 | 会话变量存 Stage / 触达计数 | 🔴 跨轮持久化、`get 副本 + commit` 语义、并发安全，都别扭 |
| CONFIRM 人工确认 | 人工审批节点 | ⚠️ 语义不同：那是"流程暂停等审批"，这里要的是"草稿进运营工作台队列" |
| 评估归因 | 只有运行日志 | 🔴 按层归因做不了——只能整体跑，失败无法定位到层 |

---

## 二、四个本质区别

| 维度 | Dify | 本项目 |
|---|---|---|
| **策略归属** | 改策略 = 改画布 = 技术动作 | 策略是 `MATRIX` / JSON，运营可自助维护——**策略即配置** |
| **可测试性** | 只能整体试跑，失败看日志猜 | 每层纯函数可单测；评估集可按层归因（见 `eval/attribute.py`） |
| **控制流透明度** | 控制流藏在画布里，diff 不了、review 不了、回滚靠快照 | 每次变更就是 git diff，能 code review |
| **强制性** | 风控是"一个节点"，链路上可以绕 | `run()` 里风控是唯一出口，绕不过去 |

一句话概括：**Dify 把"流程"产品化了，但这个项目的核心资产不是流程，是策略和度量。**

---

## 三、什么时候该用 Dify（公平地说）

它不是劣等选项，是**不同阶段**的选项：

- 规则数少于十条、还在探索 prompt 怎么写
- 团队没有工程师、要快速给老板看个能跑的东西
- 只要 ③⑤ 两层单独拿出来（意图分类 + 话术润色），我会直接建议用 Dify 搭

判断标准就一条：**当"什么时候该说什么话"成为业务核心竞争力、且需要被度量时，从平台搬到代码。**
本场景在第一天就满足这个条件。

## 四、半天实验计划（强烈建议真的做一次）

口头说"平台做不了"没有说服力，**试过并能说出具体卡点**才有。花半天：

1. 在 Dify 里拖 ③意图识别 + ⑤话术生成 两个 LLM 节点，接上本项目的 `data/knowledge.json`
2. 用 IF/ELSE 节点尝试复现 `policy.MATRIX` 里任意 10 条规则
3. 把卡住的点记下来，预期会撞上这几堵墙：
   - 复合键 `(Stage, 意图)` 的组合爆炸，分支节点指数增长
   - "无卡片则转人工"的兜底语义，在分支节点里表达很绕
   - 触达计数的跨轮读写，会话变量行为和预期不一致
4. 产出物：一页记录（哪一层卡住、为什么、怎么绕、绕的代价）

## 五、面试 30 秒回答

> "我两个都做过。Dify 拖原型一天就通了，但当我尝试把 50 条 `(Stage, 意图)` 策略矩阵
> 放进去时，发现三条路都走不通：拖 50 个分支节点没法维护；塞进代码节点等于把
> Python 藏进画布，失去了平台的意义；留在画布里则运营改一条策略就要动工作流。
> 更致命的是评估——我的评估框架能把错判归因到具体层（闸门 / 意图 / 策略 / 卡片 / 风控），
> Dify 只能整体重跑。所以最终模型只保留在理解与生成两个节点，控制流全部回到代码。"

**追问预案**：

- **"LangChain 呢？"** → 同一套逻辑。LangChain 擅长编排 LLM 调用（Chain/Agent 抽象），
  而本项目的核心是策略与度量，不是编排。用了框架反而把控制流藏进抽象层，
  出问题只能读源码；手写的每层都是 20 行内的纯函数，能单测、能留痕、能被运营改。
- **"那你的方案缺点是什么？"**（诚实的自我批评很加分）→ 推运营成本转移到了写代码的人身上：
  策略改动要发版（除非把 MATRIX 配置化，这是待办）；没有 Dify 那种开箱即用的
  模型管理 / 渠道发布，接企微通道要自己做；对纯业务同学门槛高。
  **如果场景只是"问答机器人"，我会选 Dify，不丢人。**
